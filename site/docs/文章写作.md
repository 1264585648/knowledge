# 文章模板与写作指南

页面骨架已接入正式 Astro 内容管线。日常新增文章只改 Markdown，不复制 HTML，不修改阅读器脚本。

## 1. 最快的新建方式

在 `site` 目录、Node.js 22.12 或更高的项目支持版本下运行：

```bash
npm run new:article -- rag-next-lesson --topic rag --order 3 --title "我的下一篇文章"
```

默认创建 `content-example/rag-next-lesson.md`，状态为 `draft`，标记 `sample: true`。同名文件存在时会报错，不覆盖。也可以复制 `templates/article.md` 到内容目录。模板文件本身不被内容加载器扫描。

填入摘要、正文，将 `status` 改为 `published`，确认发布日期不晚于当前构建时间，再运行：

```bash
npm run dev
# http://localhost:4321/articles/rag-next-lesson/
```

草稿和未来发布日期在开发预览里同样不生成页面。发布日期按 UTC 解析；到达未来日期后还需要重新构建，不会自行定时发布。

`npm run dev` 仅用于本地设计预览，不经过 Worker，不能用于公开托管或权限验收。生产仍使用原有私有内容构建与 Worker 访问检查。

## 2. 每篇只维护这些字段

```yaml
---
title: "文章标题"
summary: "一两句话说明本文的内容。"
publishedAt: 2026-09-19
status: published
topics: [rag]
order: 3
sample: true
tocDepth: 2
# cover: /media/rag-reading-cover.webp
# coverAlt: "窗边的书本与花瓶"
---
```

`title`、`summary`、`publishedAt`、`status`、`topics` 必填。`order` 是可选的专题阅读顺序（正整数）；未填写的文章排在已编号文章之后，再按日期升序、文件名排序。首页仍按发布日期从新到旧排列。

`topics` 可以有多个值，第一个是主专题，用于面包屑和上下篇；各专题目录均可出现同一文章。现有专题 ID 见 `src/data/topics.ts`，增加全新专题时只需在该文件注册一次。未知专题会令构建报错。

`cover` 是可选的站内 `/media/` 图片地址，填写时必须提供非空 `coverAlt`；不填写则不渲染横幅。图片需放入 `site/public/media/` 对应路径。只接受同源 webp/png/jpeg/avif 路径，不接受远程跟踪图片地址。示例横幅沿用设计稿原有裁切素材，仍只是设计预览资产，没有新增版权或高清授权声明。

`tocDepth` 默认 2，只显示 `##`；设为 3 时包含 `###`。目录文本、锚点与高亮从真实 Markdown 标题生成，不要求手写 ID 或章节容器。

文件名须为小写英文 slug，例如 `rag-next-lesson.md`，不支持嵌套 slug。文件名决定 URL 和批注标识；已发布后不要随意改名。只改标题不会改变文章地址。

## 3. 正文怎么写

正文从 `##` 开始，不再重复一级标题；标题由模板读取 `title` 渲染。

使用普通 Markdown 的段落、粗体、列表、引用、表格、代码围栏、图片和脚注。模板负责颜色、留白、链接、溢出滚动和手机排版。无需加入 `.article-section`、HTML 侧栏或页面脚本。本轮不引入 MDX，也不要求安装新框架。

复杂教学案例可先用引用块、列表或表格表达；后续需要特殊内容组件时再扩展 MDX。Markdown 内容只应来自可信作者，不把未经审查的用户 HTML 当作文章构建。

## 4. 两篇示例与真正的内容入口

- `content-example/what-is-rag.md`：迁入最新的三部分正文，稳定地址 `/articles/what-is-rag/`，有封面，二级目录。
- `content-example/rag-template-example.md`：模板验收样例，不是 RAG 第二课；无封面，含三级目录、表格与代码，验证上下篇和独立批注。正式编写第二课时可删除该示例，使用 `order: 2`。
- 仓库根部 `高保真/` 与 `内容/RAG/` 保留为此前设计与稿件记录；不再是正式站点的内容读取入口。后续只编辑当前 `CONTENT_DIR` 中的 Markdown，不要同时维护多份正文。

发布流程为：写 Markdown → 校验与构建 → 经过原有发布流程。改一份模板会影响全部文章；改一篇 Markdown 只改变其内容和自动关联信息。

## 5. 骨架与内容的边界

```text
src/components/ArticleReader.astro   三栏共享布局与正文 slot
src/components/TopicTree.astro       已发布专题／文章树
src/components/ArticleHeader.astro   标题、摘要、日期、封面
src/components/ArticleToc.astro      自动章节目录
src/components/ReaderTools.astro     通用提问／批注控件
src/components/ReaderIcon.astro      共享图标
src/pages/articles/[id].astro        render(article) 并注入骨架
src/content.config.ts               字段定义与校验
src/data/article-utils.ts            阅读排序、上下篇、阅读时间
public/public/article-reader.css     从 article-v2.css 提取的生产基础样式
public/public/article-content.css    普通 Markdown 的排版扩展
public/public/article-reader.js      无文章硬编码的阅读交互
```

基础 CSS 与原型 `高保真/assets/article-v2.css` 在迁移时字节相同；参考源 blob 为 `df1db743d6ca221a3815682b975c846d23435145`。原高保真不覆盖。日常生产样式仅维护站点共享文件，不为每篇增加独立样式。

## 6. 批注、收藏与权限

批注使用 `zhiye:article:v1:{文章ID}:notes`，收藏使用同前缀的 `bookmark`；主题与最近阅读偏好全站共用。旧原型及旧阅读器的存储键不迁移、不删除、不覆盖。旧记录仍保留在原页面与原存储中。

同一浏览器中的不同文章相互隔离，但不是不同登录用户的私密账号存储。没有跨设备同步，也没有新增 AI 或评论后端。提问仅本页暂存，刷新清空。

批注支持引用、编辑、确认删除和 Markdown 导出。章节标题改名时保留旧摘录，失效的定位链接不再显示。存储损坏、配额异常、跨标签并发时不覆盖旧内容，会提示暂存与导出。

公开仓库只放示例。私有内容继续使用公开仓库以外的 `CONTENT_DIR`，新建命令也会遵守该目录，创建 `sample: false` 草稿，并拒绝写入仓库内部的自定义私有目录。敏感正文与图片都不要提交到公开仓库。不要把构建出的 `dist` 上传到绕过 Worker 的静态托管服务。

本轮没有修改 Worker、OAuth／关注验证、数据库、生产构建保护或部署开关。没有部署 Cloudflare。


新增 Node 测试覆盖发布过滤、阅读顺序、上下篇、阅读时间、纯 Markdown 写作与新建命令防覆盖。新增浏览器测试直接读取 Astro 构建产物，在测试专用 HTTP origin 上检查自动目录、两篇批注隔离、刷新恢复、搜索、选文、导出、移动抽屉、14 个视口宽度与存储异常。该路由拦截仅在测试代码中，不是应用的鉴权后门；原有真实 Wrangler 访问控制测试保持独立运行。
