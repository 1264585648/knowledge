# 知页 · 实施方案

更新：2026-09-18。范围：将现有高保真逐步迁移为可维护的知识站；Cloudflare 免费方案优先；必须通过可信的关注验证才能读取内容。

## 1. 已确定的架构

- Astro 静态生成页面，TypeScript 编写交互与服务端，沿用「UI规范」里的原生 CSS Token。
- 单个 Cloudflare Worker + Static Assets。Hono 提供入口；权限核心使用标准 Request/Response，便于独立测试。
- D1 存用户、平台身份、会话、关注有效期和一次性验证挑战；不在运行时编译 Markdown。
- 现有「UI规范/」「高保真/」保持不变，正式应用放在 `site/`。
- 正式文章从私有内容源构建；本公开仓库只保留明确标注的示例内容。代码公开不代表内容公开。
- 构建时生成文章与专题关联、目录、只含标题/摘要的搜索索引；这些产物也必须经过鉴权。

```text
私有 Markdown → Astro 构建 → Static Assets
                                  ↑
访问请求 → Worker/Hono → D1 权限检查 → 通过才读取 ASSETS
                    └→ 未通过：公开访问说明页 / JSON 拒绝响应
```

## 2. 不得省略的访问规则

正式首页、专题总览、专题详情、文章、搜索索引、文章配图与附件默认全部受保护。只公开访问说明、隐私说明、健康检查和明确列出的基础 UI 文件。

`assets.run_worker_first = true`。禁止将「先返回完整文章，再由 JavaScript 遮挡」当作权限系统。不得按 `.js`、`.json`、`.html` 或图片扩展名整体放行；不得设置会把未知地址返回首页的 SPA fallback。

会话使用 32 字节随机 Token，D1 只存 SHA-256 哈希；Cookie 使用 `HttpOnly; Secure; SameSite=Lax; Path=/`，生产使用 `__Host-` 前缀。逐次检查用户状态、会话有效期/撤销状态，以及同一个平台身份的关注授权与有效期。关注失效和登录失效是不同事件。

受保护响应、拒绝响应和鉴权接口设置 `private, no-store`；暂不使用 Service Worker、离线正文缓存或公共整页缓存。数据库故障、缺失配置或平台故障不能自动放行。退出操作使用 POST，并验证同源 Origin。

## 3. 尚未确定的关注平台

用户尚未指定 GitHub、微信公众号或其他平台，也未确定取消关注后的失效时限。

基础阶段默认 `AUTH_PROVIDER=disabled`，不创建公共测试账号、万能口令、假登录或「我已关注」直接解锁接口。可以先完成会话和授权读取逻辑，但不能据此宣称第三方登录已完成。

平台接入必须实现：可信身份确认 → 服务端关注核验 → 写入限时授权 → 创建站内会话。只接收可信平台响应；浏览器提交的 username、openid、followed=true、截图等不是授权依据。

GitHub 候选路线：OAuth 身份确认，服务端查询 `GET /user/following/{target}`。204 与 404 区分关注与未关注；401、403、429、5xx 均需独立处理。不得把仓库 Star/Watch 当作关注账号。微信公众号需要先验证实际账号的权限、接口和平台规则，暂不承诺任意账号均可免费实现。

取消关注后的策略在接入阶段确认：可信事件撤销，或有明确复核间隔的限时授权。禁止将限时复核宣传为实时取关失效。

## 4. 数据模型

| 表 | 用途 |
| --- | --- |
| users | 站内用户及停用状态 |
| identities | 稳定的平台用户 ID，与站内用户绑定 |
| sessions | Token 哈希、绑定身份、有效期、撤销时间 |
| follow_status | 身份 + 关注目标的验证状态、核验时间、有效期 |
| auth_challenges | 短期一次性挑战、浏览器绑定、过期/消耗时间 |

会话直接关联平台身份，而非仅关联站内用户，避免使用另一平台的关注记录误授权。查询使用参数绑定；不记录 Cookie、Token、回调 code 或私有正文到日志。挑战消费需原子处理，回调必须防重放。

## 5. 分阶段实施与验收

### P0：工程基础（本轮开始）

建立 Astro + Hono Worker 骨架、配置模板、SQL 迁移、会话权限核心、公开访问说明页；迁移首页和专题结构，加入示例文章与受保护搜索。

验收：没有 Token、伪造 Token、撤销/过期会话、过期关注都不能读取内容；D1 出错时返回拒绝；HTML 和 JSON 直链不能绕过；原设计目录不被覆盖。

### P1：真实关注验证（上线前置）

确认平台及权限后，接入 OAuth/可信回调、身份绑定、关注验证、授权签发、限流、必要时 Turnstile 服务端验证、失效与重新核验。所有真实账号与密钥通过部署环境配置，不进入仓库。

验收：真实关注用户通过；未关注用户失败；错误平台身份不能借用权限；外部接口异常失败关闭；过期及撤销可以复测。未完成 P1，网站不得标注为生产可用。

### P2：真实内容与发布

私有内容仓库与只读构建凭据、内容更新触发构建、移除示例、文章发布流程。公开代码 CI 只使用公开示例，不向外部 PR 提供内容凭据，不上传包含正文的公开构建产物或 source map。

### P3：部署与回归

创建实际 D1，执行远程迁移，配置域名/回调/Secrets。验证自定义域名、workers.dev、预览入口都执行相同权限；测试移动端、键盘操作、搜索、数据库故障与额度边界。记录实际 Worker CPU 与请求量后再判断免费额度是否足够。

## 6. 免费方案预算原则

Worker 鉴权调用计入 Worker 请求；不能把受保护页面当成无限免费的静态访问。D1 按处理的行数计量，索引和查询范围影响额度。构建时完成较重的内容处理，不在每个页面/资源请求时都调用关注平台，不逐次写入访问日志。免费额度耗尽时拒绝受保护请求，不旁路鉴权。域名、平台资质等成本不包含在 Cloudflare 零费用目标中。

额度与条款可能改变，正式部署前按官方文档复核；本文件不承诺无限访问、固定承载人数或总体永远免费。

## 7. 测试与交付约定

权限核心提供无需第三方包的 Node 测试入口，同时配置 Vitest/Playwright。实际通过的测试、未执行的构建或部署必须分别记录，不能用「写了测试」代替「测试通过」。首次依赖解析后应提交真实生成的 lockfile；不能伪造 lockfile。

`astro dev` 只用于本机视觉预览，不包含 Worker 鉴权，禁止用于公开托管；权限验收使用 Wrangler。没有部署凭据时只提交工程，不擅自创建付费资源或宣布部署成功。
